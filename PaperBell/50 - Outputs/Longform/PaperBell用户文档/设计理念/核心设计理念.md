> [!hint] Welcome!
> 欢迎来到 PaperBell 5.x!
> 从 `5.x` 版本开始，`PaperBell` 系列产品的设计可以浓缩成一套方法论，及背后的四点核心理念：模块化、自动化、概念为轴、本地优先

制作这个仓库的初衷，是把我用 Obsidian 管理学术生活的思考整理分享给你。并使用一套预设的工作流来实现这种理念。从一个人的业余分享，到一个持续维护的小团队；从互联网开源社区懵懂走来，到如今全面拥抱 AI 浪潮。PaperBell 迄今已经走过了近四个年头，仍然是众多科研人、研究生首选的笔记工具。

## 理念一：模块化

在 `PaperBell` 项目实践的早期，我们就提出了 “学术生涯是一系列要素” 的累积的概念：

- 🧑‍🔬 **学者**：学术共同体本质上是一个小圈子，你的研究生涯就是不断发现并受到其他学者启迪的过程。
- 🤔️ **概念**：概念是学术共同体频繁使用的术语，是学术殿堂的基本拼图——在 `PaperBell` 里它就是一张张[[概念卡]]。
- 📑 **论文**：论文是学者发声的途径，是学术共同体交流的基础；作为输入，它携带[[关键词]]。
- 📁 **项目**：每个[[科研项目]]都可能持续数年（通常半年以上，单篇论文不算），并产生一系列研究成果。
- 🗺️ **地点**：每个人都是「地理人」，无论是你隶属的机构、还是你参加的活动，都会发生在某个具体的地点。
- ... ...

但随着知识的不断积累，我们发现以列表管理这些不同形式的要素逐渐变得膨胀。比如读过的科研论文和读过的网页文章要放在一起吗，学术会议和野外调研是否应该分开不同要素记录？对于这些问题没有一个固定的答案，完全取决于你划分的**类别粒度**。因此，我们一直在思索如何使用一个比要素更高层的框架来整合这些要素，协调不同要素间的联系和分工。

在 5.x 版本种，`PaperBell` 独家设计了[[CIMPO_学术生涯管理框架]]，通过把整个仓库分成五层，正好对应五个带编号的文件夹，首字母连起来就是 **CIMPO**（`00 - Obsidian` 存放配置与脚本，不计入字母），看看是不是让你的笔记管理结构更加 **Simple** 了?：

| 层                    | 文件夹             | 是什么                           |
| -------------------- | --------------- | ----------------------------- |
| **C · Concepts 概念**  | `10 - Cards`    | 你写作时真正会用到的[[概念卡\|概念]]，一个有界的词表 |
| **I · Inputs 输入**    | `20 - Inputs`   | 读到的材料：论文、图书、网络文章，携带[[关键词]]    |
| **M · Metadata 元数据** | `30 - Metadata` | 学者、机构、日记——「人 / 地 / 时」的流水账     |
| **P · Projects 项目**  | `40 - Projects` | 长周期的[[科研项目]]，最顶级的管理层          |
| **O · Outputs 输出**   | `50 - Outputs`  | 你亲笔写下的[[输出系统\|草稿与长文本]]        |
|                      |                 |                               |
通过这样模块化的设计，不同学科、不同需求、不同使用强度的用户应该都能够在该框架下找到自己每篇笔记的位置，并在不破坏整体性、交互性的基础上进行功能拓展。

> → 想深入理解每一层，可以阅读这几张概念卡：[[CIMPO]]、[[科研项目]]、[[输出系统]]、[[关键词]]、[[概念卡]]。

## 理念二：自动化

从 `PaperBell 3.x` 开始，为了可持续地维护项目，我们团队开始采取 “**框架开源、自动化工具闭源**” 的收费原则。但为了应对模块化后不同的自动化需求，我们针对每个模块都设计了一个配套的插件。

![[modules_screenshot.png]]

这些模块插件既可以通过一个 “PaperBell” 主插件进行聚合，实现完整的仓库功能；也可以单独下载安装，支持用户在某个方面的自动化需求。订阅 `PaperBell` 会员并在主插件里输入注册信息，就可以激活使用全套 CIMPO 系统插件，并且 AI 相关功能也可以在一处输入密钥供整个配套插件使用。所有模块插件都将会不断更新，针对 CIMPO 系统里的每个模块的常用功能逐步进行自动化。

## 理念三：概念为轴

你有没有想过这些问题——

- 大家经常看的“baidu 词条”、“Wiki 百科”这样的知识系统是如何运作的？
- 为什么无论是提交论文还是申请科研项目都需要填写五个关键词？
- 检索一个领域文献时，许多同义词近义词怎么处理？

**这些问题的答案都和「概念」这个有趣的东西有关。**

- 无论是百度还是维基百科，概念都是组成知识站的重要“原子”，这些概念（或称为词条）之间编织成一张语义网络，反映一个知识在系统中的位置。用户可以通过概念之间的共现、近义、包含等关系，定位对自己有用的参考资料。
- 论文、基金、甚至是互联网上的大多数数据库检索，都依赖于基于概念、关键词的语义系统。所以一篇文章通常都会围绕三到五个关键词进行组织。而一个学者生涯的成长，也可以被看作是“抽象层级更高”，会被众多词条所锚定。
- 其实从语言学的角度来说，概念存在不同的抽象层级。低抽象层级的概念指涉具体的实体，而高层级的概念则包含众多低层级的词汇。语言学家和档案学家已经发明了一整套能够反映自然语言词元间关联的语义系统。来反映这些概念关系。

正因如此，这些概念其实是组成学术生涯的关键。

本来维护这样一套知识系统固然系统，但是也非常昂贵。但是在人工智能大语言模型的加持下，我们的“自动化”理念在这里也逐渐变得可能。`PaperBell` 它借用了国际公认“简明知识管理系统” [SKOS](https://www.w3.org/TR/skos-primer/) 的词表模型概念，结合和 Andrej Karpathy 的 [_llm-wiki_](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 个人知识库构想，打造了一套专门为科研人设计的概念叙词表。

这是 `PaperBell` 最关键的一处设计。我们把"给材料贴标签"和"我写作时用的词"分成两条轴。对于输入的关键词，使用大语言模型进行清洗和打标签，然后让标签在自己的概念库中产生关联。输出终端则在概念库中精选自己关心的词进行写作。输入端任由其自然增长，输出端只要选择关键词就能关联所有笔记素材，两条轴互不干扰：

- **[[关键词]]（输入端）**：自由、无上限。导入一篇论文时，把它的标签原样丢进来即可，用来帮你日后**快速回忆**某份材料。
- **[[概念卡]]（输出端）**：少而精、有界（软上限约 50 张）。它是你**写作时**真正会用到的术语，按需创建。

在此基础上，概念卡通过"挂靠关键词"**单向反查**输入——所以导入论文**不需要**做任何受控标注，连接的维护只发生在概念卡一侧，而`PaperBell` 自动帮你建立关联：

- **项目-笔记**：自动关联与某个[[科研项目]]有关的所有笔记。
- **概念-想法**：把一闪而过的 `#想法` 关联到相关的[[概念卡]]。
- **论文-学者**：关联收藏的学者和读过的他们的论文。
- **概念-输出**：根据选择的关键词找到可以用来论文写作的素材。
- ... ...

而科研灵感正产生于这些已有知识之间建立新的连接。

> [!tip] 为什么这样最省力
> 输入是杂而多的（越多越好，尽管捕获），概念是少而精的（它是你的写作词表）。挂靠只在概念卡上维护一次，就能连上所有现在和将来携带这些关键词的论文与学者。

## 理念四：“本地”优先

正如前文里已经提及的那样，我们已经拥抱了 AI。这一定会联网，许多时候还需要你把数据传给你选择的模型，但为什么我们仍然在强调本地优先呢？因为我们对未来科研工作的设想，AI 一定会成为重要基础设施，一味强调离线肯定是不可取的。但我们和许多科研工作者一样，对 AI 生产的内容要十分小心，不能让它代替你做科学决策。因此我在这里想定义一种“**知识本地优先**”的概念，具体包括：

- 知识库内的所有输入来源于你的优选，而不是 AI
- AI 负责维护已有内容实体，尤其是建立实体间链接
- AI 只能处理你主动提交的内容，在受控范围内
- 所有内容进行本地审计，工作不依赖于互联网加载
- 只有主动点击提交（或提前授权）才能与互联网交换信息

> [!tip]
> 在上述理念的基础上，我们也会尽力使用 AI 来为用户节约时间和精力！比如 [[概念卡使用场景]] 里面提到的  LLM-Wiki 就是我们理念的最佳实践！
